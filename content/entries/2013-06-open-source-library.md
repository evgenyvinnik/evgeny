A small library with an unreasonable number of downloads. I still merge pull
requests from strangers on Sunday evenings.

It does one thing, has no dependencies, and has not needed a breaking change
since the second release. That combination is most of why it gets used.

Maintaining it taught me to say no in writing. The issue tracker is a record
of features that would each have been reasonable and would together have
made it into something nobody wanted.

The API has survived because it was too small to get wrong. Every time I
have been tempted to widen it I have written the wider version, used it for
a week, and thrown it away.
